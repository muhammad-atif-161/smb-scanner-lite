What is SMB Scanner Lite?

It is an evidence-first external security posture tool for small and medium businesses. From the public internet it checks email authentication, DNS integrity, TLS, security headers, and whether risky services such as SMB are reachable. The public edition can only do this against five testing domains.

Who is it for?

Owners and IT helpers at small firms, students of defensive security, and anyone who wants a clear outside view of a domain they are allowed to test. It is not an attack tool.

Does it hack servers?

No. Checks are read-only observations: DNS queries, TLS handshakes, HTTP headers, and a single unauthenticated SMB negotiate that reads dialect and signing. It does not log in or exploit vulnerabilities.

Which domains can the public download scan?

Only example.com, example.org, example.net, scanme.nmap.org, and badssl.com. Every other target is blocked before any network request.

What does evidence-first mean?

Each conclusive finding includes the observation that supports it. If a server does not answer in time, the result is inconclusive rather than a false failure. The project calls this standard “no claim without evidence”.

Is the full source code public?

No. The complete engine, control catalog and private tests stay in a private repository. This public repository holds the website, documentation, and the locked sandbox edition.

What is a posture score?

A 0–100 summary across the controls that actually completed, with a letter grade. It is a communication aid for an owner, not a guarantee and not a penetration-test certificate.

Do you store my scans or my name?

This website does not run scans and does not collect consent names. The sandbox tool writes the consent ledger only on the computer where you run it.

How was the tool made?

Muhammad Atif wrote it in Python as separate check modules plus a scoring model grounded in public RFCs. The sandbox lock and consent proof were added so a public demo could exist without enabling misuse.

Where can I find the methodology?

The methodology page explains what is measured, how scoring works, how evidence is attached to findings, and the difference between a failed check and a confirmed vulnerability.

Who should I credit?
