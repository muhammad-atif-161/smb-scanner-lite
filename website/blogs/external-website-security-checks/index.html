Website security checks worth doing by hand

Not every useful check needs an exploit. Some of the first questions are visible from an ordinary browser request.

Muhammad Atif Updated 4 November 2026 2 min read

Worth remembering

  • A browser padlock establishes connection properties, not application trust.
  • Header and certificate checks are useful but incomplete.
  • The current online DNS/email beta does not run these website tests.

Before commissioning a deep application review, a site owner can check a few basic properties that any visitor's browser encounters. These observations can reveal operational oversights. They are not a substitute for vulnerability testing, authenticated access review or code audit.

Start with the actual hostname

Open the precise address customers use. Confirm it resolves, the TLS certificate covers the hostname, the chain is trusted by your client and the certificate is valid. Remember that a valid certificate proves a particular connection, not that the website behind it is safe.

Inspect redirects rather than assuming them

Test the public HTTP entry point and confirm that requests reach the intended HTTPS host. Look at each hop for unexpected hosts or mixed-content resources. A redirect policy is a deployment decision; it should not happen to work only on the home page.

Review headers in context

Security headers such as HSTS, CSP, X-Content-Type-Options and framing restrictions can reduce specific browser-side risks. Their absence is not equally serious on every site, and a policy that exists but is misconfigured may be worse than a carefully scoped exception. A report should quote the exact header and response where it was observed.

Check what is publicly reachable

Review public services against your own inventory. Do not probe third-party systems or attempt access to endpoints you are not authorized to test. Service reachability is an observation, not proof of a remotely exploitable vulnerability.

Know where these checks stop

They cannot determine whether an application suffers authorization flaws, injection, broken session handling or vulnerable dependencies. Those require different methods and permissions. The first release of SMB Scanner Lite's hosted service checks DNS and email policy only; the website checks in this article are educational steps for your own site.

The service boundary: The prepared online assessment verifies domain ownership and inspects public DNS/email policy. This article may discuss broader security practices; it is not a promise that the hosted worker performs those checks. See the actual scan scope.
