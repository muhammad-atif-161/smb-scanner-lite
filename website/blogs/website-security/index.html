Blog · Website and TLS

Website, TLS and browser security

A padlock means the connection is encrypted to somebody. It does not mean the site is trustworthy, patched or safe. These guides separate the reassurance from the things that are actually verifiable from outside.

1 post Updated 31 October 2026 Cluster guide

Website security conversations tend to collapse two different questions: is the connection private, and is the site well built? TLS answers the first. Response headers, redirect behaviour and certificate hygiene start to answer the second, and all of them are visible in a single unauthenticated request.

None of this replaces a code review or a penetration test. What it does is catch the misconfigurations that were never a decision — the missing HSTS header, the certificate covering the wrong hostname, the HTTP version of a page that quietly still works.

Every post in this cluster ends with the same question: what would you do on Monday? Where a check can be run by hand, the command is in the post. Where it cannot, the post says so rather than implying a tool will handle it.
