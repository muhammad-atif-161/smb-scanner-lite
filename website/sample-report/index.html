What is in the report

From technical checks to actionable context.

A report is only useful if a non-specialist can read it. Each section answers one question: what is the score, what failed, what is the proof, and what should I do next.

  • Score, grade and how many controls actually completed
  • Findings grouped by severity, with plain-language explanations
  • The evidence string behind each conclusive result
  • Inconclusive results shown separately, never merged into a failure
  • The consent receipt that proves authorisation was given first

DNS A/AAAA resolution

The name resolves to both IPv4 and IPv6 addresses, so visitors can reach the domain.

Resolved example.com -> 104.20.23.154, 172.66.147.243, 2606:4700:10::ac42:93f3, 2606:4700:10::6814:179a

DNSSEC validation

The zone is signed and the chain validates against the parent delegation.

Zone signed with validated RRSIG and parent DS delegation.

SPF hard-fail policy

Only the domain itself may send mail; senders outside the policy are rejected.

v=spf1 -all (strict no-mail policy for reserved domain).

DMARC enforcement

Mail that fails authentication is rejected rather than merely monitored.

v=DMARC1; p=reject; sp=reject; adkim=s; aspf=s

RFC 7505 Null MX

The domain publishes a null MX, so it does not accept mail at all.

MX 0 . published indicating domain does not accept e-mail.

TLS 1.2/1.3 and certificate

A valid certificate covers the domain over a modern protocol.

Valid X.509 certificate covering example.com over TLS 1.3.

HTTP Strict-Transport-Security

The header is not enforced, so a browser may be allowed to downgrade to plain HTTP.

Strict-Transport-Security header not enforced on reference landing page.

Content-Security-Policy

No content security policy is published, so the browser has no extra instruction to work with.

Content-Security-Policy header absent on static reference response.
