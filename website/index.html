What it does

Security findings you can actually understand.

SMB Scanner Lite evaluates selected, externally observable security controls and organises the results into a report built to make technical findings easier to explain. It is an external assessment — not an audit of an organisation’s internal systems.

01

Assess

You choose a domain you own or have written permission to assess. The tool checks only what is publicly observable from outside, and it never sends a credential or an exploit.

02

Understand

Findings are grouped into the categories that actually matter — mail locks, DNS integrity, transport, browser headers, and service exposure. Every line quotes the observation behind it.

03

Prioritize

A posture score and a letter grade summarize what completed, and each finding shows what to look at next. Nothing is graded that was not measured.

Capabilities

What the assessment actually checks.

The full catalog holds twenty-two controls in five groups. The public sandbox demonstrates the same standard on a read-only subset. Expand a category to see the individual checks.

DNS & domain security

Does the name resolve, is the zone signed, and can a stranger copy or redirect it?

  • Address resolution and record presence
  • DNSSEC chain validation
  • CAA — which certificate authorities may issue for the domain
  • Zone transfer attempts
  • Stale or reused name records
Email authentication

Whether a stranger can send mail that looks like it came from the domain.

  • SPF — does it actually fail unauthorised senders
  • DMARC policy, and whether it enforces or only monitors
  • DKIM key length and presence
  • MX records, including a domain that has chosen to receive no mail
Network & service exposure

Which high-risk services answer from the public internet, and whether they ask for a signature.

  • Protocol-checked reachability of high-risk ports
  • SMB on 445 through a single unauthenticated negotiate
  • Remote desktop reachability
  • No login attempt, no share listing, no payload
Transport & browser headers

How carefully the site treats the browsers that visit it.

  • TLS versions offered and certificate validity
  • HTTP to HTTPS redirect
  • HSTS, Content-Security-Policy, clickjacking and sniffing protection
  • Cookie, CORS and referrer policy

  • Posture score and letter grade
  • Severity assigned to each finding
  • The evidence string behind every conclusive result
  • Inconclusive results reported separately from failures

How it works

Three steps, no agent required.

Choose an authorised domain, let the tool look from the outside, then read a report that tells you what it saw.

01

Select an authorised domain

Pick a name you own or have written permission to assess. In the public edition the choice is already limited to five testing domains.

02

Run the assessment

Read-only queries only — DNS, mail policy, TLS handshakes, response headers and a single protocol-level probe. No login, no payload.

03

Review the report

Score, grade, findings, the evidence behind each one, and what to look at next. HTML, JSON or text.

Trust & privacy

What the public edition will not do.

Trust comes from clarity here, not from badges. These are the boundaries of the public demo.

Authorised use

Only domains you own or have explicit permission to assess. The public download is hard-locked to five free testing domains, and it refuses anything else before a network request is made.

Transparent limitations

Read-only external observation of a defined control set. It is not a complete audit, it does not exploit anything, and a timeout is reported as inconclusive rather than as a failure.

Privacy information

This website is static: it does not run scans, collect names, or sell data. Consent receipts are written to the machine you run the sandbox on. Read the policy before you start.

Privacy policy

Consent before action. Every sandbox run records a hash-chained receipt on your own machine. The website never receives it.

Methodology

Built around evidence, not unexplained scores.

The rules behind the checks, the scoring and the limitations — in the same order a reviewer would ask about them.

What is actually measured?

Only what a stranger on the public internet can observe: DNS records, mail authentication policy, TLS handshakes, HTTP response headers, and whether a small set of high-risk services answers a protocol-level probe. Nothing behind a login, nothing on a private network.

How is a score built?

Each completed control contributes to a 0–100 posture score, weighted by how much it matters to a small business. The score only covers controls that finished. A control that timed out is excluded from the score and reported separately as inconclusive — so a silent target cannot inflate or deflate the number.

A failed check is not a confirmed vulnerability

A failed control means the published expectation was not met. It is not an exploit, and it is not a proof that a system is compromised. Treat every finding as a reason to look, not as a verdict.

What the score does not measure

It does not measure the applications behind the domain, the people and processes inside the business, physical security, or anything that requires authentication. It is a communication aid, not a penetration-test certificate and not a guarantee.

How to verify a finding yourself

Each conclusive result quotes the record, header or handshake that produced it. Copy it, then run the equivalent query from a machine outside your network. If the answer differs, the finding is stale.

FAQ

Questions people actually ask.

What is SMB Scanner Lite?

An evidence-first external security posture assessment for small and medium businesses. It looks at the public footprint of a domain — mail locks, DNS integrity, TLS, browser headers and service exposure — and reports only what it observed. The public edition runs against five testing domains.

What does the posture score mean?

A 0–100 summary across the controls that actually completed, plus a letter grade. It exists so an owner can talk about priority with an IT helper. It is not a guarantee and not a certificate.

Can I scan any domain with the public demo?

No. The public edition accepts exactly five testing domains: example.com, example.org, example.net, scanme.nmap.org and badssl.com. Every other target is rejected before a network request is made.

Do I need authorisation to assess a domain?

Yes. You should only assess a domain you own or have written permission to test. The full engine is distributed only for authorised assessments; this repository publishes the locked sandbox edition.

Does the tool perform a complete security audit?

No. It is a read-only external observation of a small set of controls. It does not log in, exploit anything, or inspect internal systems.
