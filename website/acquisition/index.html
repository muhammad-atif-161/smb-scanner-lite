1 · Project overview

SMB Scanner Lite is an evidence-first external security posture assessment tool for small and medium businesses. It evaluates a catalog of 22 publicly observable security controls, produces a weighted 0–100 posture score and an A–F grade, and attaches the observation behind every conclusive finding.

The project ships as two artefacts: a private full engine (controls, scoring, reporting) and a public sandbox edition locked to five reserved testing domains, with a public website, documentation and test suite.

It was built by Muhammad Atif as a defensive security product with an explicit "no claim without evidence" standard. That standard shapes the scoring model, the four-status evidence system and the deliberately conservative wording on this site.

2 &middot; Technical architecture

A static public surface and a private assessment engine.

Deliberately simple to operate and to hand over.

Public surface

A dependency-free static website (HTML, CSS and one JavaScript file) generated by a small Python build script and deployed to GitHub Pages. No framework, no runtime, no database, no third-party analytics.

  • Reusable design system and component layer
  • Static site generator in tools/ (Python standard library only)
  • Structured data, sitemap, robots and per-page metadata
  • Recorded assessment data served as static JSON

Assessment engine

Python 3.10+ with modules per control group and a scoring model grounded in published RFCs and vendor guidance. Reports render to HTML, JSON, CSV and TXT.

  • 22 controls across five categories with severity weights
  • Four-status evidence model including inconclusive
  • Hash-chained consent receipts with policy digests
  • Sandbox runtime with a hard five-domain allowlist
  • CLI and desktop interface

What the platform does today.

Weighted 0–100 score, A–F grade bands, per-category scores and severity on every finding.

Reporting

HTML, JSON, CSV and TXT. Executive summary, findings, technical evidence, recommendations and assessment metadata.

Consent evidence

Restricted public demo

Documentation

Methodology, control catalog, installation guide and privacy position written for technical and non-technical readers.

4 &middot; The 22 controls

The catalog is part of what you acquire.

Each control is implemented, documented and weighted. The five categories carry published score weights of 20%, 25%, 20%, 15% and 20%.

Control catalog

  • C01 — Address resolution and record presence (DNS)
  • C02 — DNSSEC chain validation (DNS)
  • C03 — CAA authorisation (DNS)
  • C04 — Zone transfer exposure (DNS)
  • C05 — Name record hygiene (DNS)
  • C06 — SPF policy strength (Email)
  • C07 — SPF record validity (Email)
  • C08 — DMARC enforcement (Email)
  • C09 — DKIM presence and key strength (Email)
  • C10 — MX and null-MX posture (Email)
  • C11 — TLS protocol versions (TLS)
  • C12 — Certificate validity and hostname coverage (TLS)
  • C13 — Cipher suites and forward secrecy (TLS)
  • C14 — HTTPS redirect and downgrade path (TLS)
  • C15 — Strict-Transport-Security (Headers)
  • C16 — Content-Security-Policy (Headers)
  • C17 — Clickjacking and MIME-sniffing protection (Headers)
  • C18 — Referrer, permissions and version disclosure (Headers)
  • C19 — High-risk port reachability (Exposure)
  • C20 — SMB negotiate exposure (445) (Exposure)
  • C21 — Remote Desktop reachability (3389) (Exposure)
  • C22 — Database and admin interface exposure (Exposure)

5 · Testing documentation

The public repository contains a reproducible test suite covering the allowlist, consent enforcement, hash-chain integrity and CLI behaviour. Every test is named, and the validation page publishes the run metadata along with the objectives and expected results.

A larger internal validation register is maintained in the private repository. Its contents are not published, and no figures from it are claimed on this site — a buyer receives it as part of due diligence, not as marketing.
